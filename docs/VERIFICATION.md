## Что проверено в браузере

1. Интерфейс остаётся одной мобильной колонкой: 430 px на широком экране и 390 px в узком окне.
2. Нажатиями мыши через Compose canvas запускаются запись, пауза и продолжение. Вызов обработчиков приложения вместо нажатий не используется.
3. Намеренный сетевой сбой отправки не создаёт запись на сервере; аудио остаётся в IndexedDB.
4. После перезагрузки страницы доступна повторная отправка; новая запись автоматически не начинается поверх несохранённой.
5. Сервер возвращает квитанцию с исходным идентификатором. Аудио удаляется из браузерной очереди после подтверждения. Скачанный оригинал совпадает по длине и SHA-256 с сохранёнными фрагментами браузера.
6. Без настроенных моделей возвращается `NEEDS_MODEL`, а не фиктивная транскрипция.
7. Через настоящий HTTP API создаётся проект и заметка; повторное распределение той же записи не создаёт дубликат и не меняет пробелы исходного текста.

## Исправленная причина предыдущего сбоя

Тест передавал асинхронную проверку IndexedDB в `wait_for_function`. В закреплённой версии Playwright сам объект Promise считался истинным результатом до разрешения в `false`. Следующая строка читала серверный список раньше завершения отправки и падала с `IndexError`.

Теперь тест отдельно дожидается HTTP-квитанции, проверяет её идентификатор, ожидает фактического опустошения IndexedDB через `evaluate` и только затем читает запись с нужным идентификатором. Дополнительно проверяется целостность аудио по SHA-256. Сбор диагностических файлов больше не скрывает исходную ошибку теста.

## Запуск

Из клонированного репозитория с установленной JDK 21: `bash run-web.sh`. Для последующих запусков без пересборки: `bash run-web.sh --no-build`. Адрес: `http://127.0.0.1:8787`.

Из готового архива `3rdBrain-web.zip`: распаковать целиком и выполнить `bash start.sh`. Здесь также нужна JDK 21; Gradle и пересборка не требуются. Архив не содержит веса моделей.

## Что пока не подтверждено этим прогоном

Настоящие веса Whisper и LLM не запускались: качество русской транскрипции, оформления и ранжирования на реальной речи ещё нужно проверить. Тест FFmpeg использует синтетический сигнал. Браузерный сценарий проверяет сохранение аудиобайта, но не качество звучания на реальном устройстве.

Создание проекта и распределение заметки в этом сквозном сценарии проверены через HTTP API, а не вводом текста в интерфейсе. Это не полный регрессионный прогон всех экранов.

iOS, Android и нативное macOS-приложение ещё не собраны. macOS/Safari и физический микрофон не проверены этим Linux/Chrome-прогоном. Общий мобильный интерфейс и бизнес-правила уже находятся в `commonMain`; нативные адаптеры остаются отдельным этапом.
