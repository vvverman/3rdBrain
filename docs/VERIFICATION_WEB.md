## Реальные модели: вход и результат

Whisper Small + Qwen3-4B Q4_K_M, без режима рассуждений. Во время проверки inference внешняя сеть отключена через `unshare --net`; поднят только loopback. До старта сервиса тест проверяет, что соединиться с внешним IP нельзя. Скачивание весов и создание тестовой речи выполняются до этой изоляции.

Распознанный и сохранённый основной текст:

> В проекте приложения нужно исправить запись голоса.
> Добавить кнопку паузы и проверить сохранение заметок.
> Старый текст удалять нельзя.

Все три фразы остались в основном тексте, отрицание «нельзя» не потеряно. Ответ LLM применён; заголовок — **«Исправление голосовой заметки»**. В этом примере исходная транскрипция уже имела пунктуацию, поэтому основной текст не потребовал изменения. Факт выполнения модели проверяется отдельно флагом `llmApplied`, а не разницей строк.

Оценки проектов, реально полученные от модели:

| Разработка приложения | 3 |

Закреплённый проект остаётся отдельной группой и не участвует в оценивании: закрепления не переопределяются LLM. Пользователь по-прежнему выбирает место сохранения самостоятельно.

Аудио: **15,6146875 → 9,3 секунды** после сокращения длинных пауз. Компактный M4A успешно декодирован настоящим FFmpeg. Скачанный оригинал совпал с загруженным файлом по SHA-256: `db8d5596e51dc57011b462894a41cbe099273caf866cdc12015ec58b7110a4cb`.

Весь сквозной сценарий занял **60,7 секунды на CI CPU**. Это не прогноз скорости Mac или телефона и не чистое время одной модели: входят распознавание, обработка аудио, оформление, два ранжирования и проверки HTTP.

После выбора проекта через настоящий API создана заметка; повторное сохранение той же записи не создаёт дубликат. Результат сохранён в [verification/real-models-2356754.json](verification/real-models-2356754.json).

## Что проверено в браузере

Сохранена проверка мобильной колонки на широком экране (430 px) и узком (390 px). Нажатиями мыши через Compose canvas запускаются запись, пауза и продолжение. Намеренный сбой отправки сохраняет аудио в IndexedDB; после перезагрузки страницы повторная отправка завершается квитанцией с исходным идентификатором. Сохранённый на диске оригинал совпадает с фрагментами браузера по SHA-256. Без моделей показывается `NEEDS_MODEL`, а не фиктивный результат. Создание проекта и идемпотентное распределение проверяются через настоящий HTTP API.

Это не полный регрессионный прогон каждого экрана с ручным вводом текста. Адаптер записи проверен с синтетическим микрофоном, не физическим устройством.

## Какие проблемы найдены и исправлены на реальных весах

1. Служебный хвост `[end of text]` нарушал разбор JSON. Убирается только известный хвост, не произвольный текст вокруг JSON.
2. Флаг `--log-disable` подавлял и сам ответ completion. Флаг удалён; пустой вывод является явной ошибкой.
3. Qwen2.5 1.5B потеряла первую фразу и поставила одинаковые оценки подходящему и постороннему проектам. Этот набор отклонён. Добавлена проверка покрытия исходного текста, выбран Qwen3 4B.
4. В первом прошедшем прогоне Qwen3 вывела служебный заголовок. Ошибка найдена при просмотре результата, несмотря на зелёный тест. Уточнён запрос, добавлен резервный заголовок из источника и отдельная проверка заголовка.

Числа, отрицания, покрытие текста и заголовок проверяются консервативными эвристиками; они не гарантируют смысловую эквивалентность. Полный транскрипт и оригинал остаются доступны независимо от принятия результата LLM.

## Запуск и границы проверки

На Mac: `bash 'Запустить 3rdBrain.command'`. Требуются установленный Homebrew для недостающих инструментов и Command Line Tools для сборки движков. Веса скачиваются автоматически при первоначальной настройке, около 3 ГБ. Адрес приложения — `http://127.0.0.1:8787`.

Сам запускной файл Mac проверен синтаксически; на физическом Mac он в этом прогоне не выполнялся. Настоящие модели и их установка проверены на Linux. Скорость, расход памяти, качество живой русской речи и работа с конкретным микрофоном ещё требуют проверки на пользовательском устройстве.

iOS, Android и нативное macOS-приложение ещё не собраны. Текущий продукт — локальный веб-клиент с сервисом на компьютере. Общие экраны и правила в `commonMain`; отдельной десктопной раскладки нет.
