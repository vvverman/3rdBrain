# Kasha — локальный ИИ для голосовых заметок и задач

**Записать → локально расшифровать → привести текст в порядок → сохранить как заметку или задачу в проект.**

Главный принцип Kasha: **пользовательские данные принадлежат устройству**. Аудио, транскрипции, заметки, задачи, проекты и работа ИИ не требуют облачного backend и не отправляются во внешние AI API. Web-версия интерфейса может общаться с локальным процессом только через `127.0.0.1`.

## Архитектура

Kasha построена вокруг отделяемого `kashaCore`:

```text
                         kashaCore
        models · domain · rules · state contracts · AI ports
                              │
                 shared Compose presentation
                              │
          ┌───────────┬───────┴───────┬───────────┐
        Desktop     Android          iOS          Web
          │            │              │            │
        files        device          device       browser
        audio        audio           audio        audio
        local AI     local AI        local AI     local API
```

`kashaCore` не зависит от UI и от конкретной ОС. Платформа реализует только то, что действительно относится к платформе: файловое хранилище, микрофон, воспроизведение, permissions/lifecycle, упаковку и конкретный локальный AI runtime. Общие модели, сортировки, правила сохранения, сценарии заметок/задач и контракты живут в Core.

Правило проекта: **если логика может работать одинаково на двух платформах, она должна находиться в общем коде, а не в платформенном приложении.**

## Интерфейс

Один общий мобильный интерфейс на Compose Multiplatform, шириной до 430 dp:

- разделы **Главная / Проекты / Задачи / Настройки**;
- после голосового ввода выбор **Заметка / Задача**, затем проект;
- проекты, заметки и задачи сортируются по алфавиту, дате создания, дате изменения или вручную;
- ручная раскладка хранится отдельно и не теряется после переключения на другую сортировку;
- ручное изменение порядка — long-press + drag;
- `Kasha UI` — единственный слой продуктовых контролов;
- продуктовые иконки — только Phosphor; motion переносится из MIT-наборов animated Phosphor, исходники и лицензии фиксируются в `third_party`;
- **Commissioner** — основной и display-шрифт; сборка проверяет русский, украинский, белорусский, казахский и четыре латинских языка интерфейса;
- светлая тема почти белая с едва тёплым жёлтым смещением, тёмная почти чёрная с едва коричневым смещением;
- splash: крупный официальный знак Kasha и версия внизу.

Восемь языков интерфейса: русский, английский, испанский, французский, немецкий, украинский, белорусский, казахский.

## Локальные данные и ИИ

Production-архитектура не предполагает аккаунт, серверную БД, облачную синхронизацию, telemetry SDK или удалённый LLM. На desktop текущий runtime использует локальные Whisper/LLM-процессы. На других платформах конкретный локальный движок может отличаться, но подключается через один и тот же Core-порт.

CI запускает отдельные guard-проверки:

- `check-local-only.py` — запрещает облачные AI/analytics/sync зависимости в продуктовых модулях;
- `check-ui-boundary.py` — запрещает обход `Kasha UI` и сторонние наборы иконок;
- `check-brand-boundary.py` — запрещает возврат старого бренда.

## Модули

- `kashaCore` — платформонезависимое ядро;
- `composeApp` — общий Compose UI, состояние экранов и web-адаптер;
- `runtime` — JVM/localhost адаптер диска, обработки аудио и локальных моделей;
- `desktopApp` — минимальная desktop-оболочка, микрофон, audio playback и packaging;
- `tests` — end-to-end и browser smoke tests.

## Сборка

Шрифт не скачивается «с latest»: `scripts/prepare-fonts.py` привязан к конкретной ревизии Google Fonts и проверяет наличие всех нужных символов. CI собирает Core, общий UI, JVM runtime, desktop и production WebAssembly, затем проходит пользовательский путь в браузере через локальный backend.
